# 시간표 서비스 워크플로우

작성: 2026-11-06(금) 11:13 KST · 상태: 임시 확정 아이디어 · 관리자 원안 6단계의 세분화본

## 한 줄 정의

학생이 말로 조건을 입력하면 AI가 조건을 정리하고, 코드가 충돌 없는 시간표를 계산하며, 대표 시간표 점수로 실시간 랭킹 경쟁이 가능한 웹.

## 역할 원칙

- AI: 말 → 조건 변환, 추천 이유, 실패 대안 설명, 칭호와 평론
- 코드: 시간표 계산, 충돌 검사, 점수 계산, 랭킹 산출
- AI 실패 시: 체크박스 입력과 고정 문구로 진행 유지

## 상세 흐름

| # | 화면 | 사용자 행동 | 시스템 처리 | 예외 처리 |
|:-:|---|---|---|---|
| 0 | 홈 | 접속, 랭킹 열람 | 최상단에 실시간 랭킹 표시 · 로그인 없이 읽기 가능 | 등록 0명이면 첫 등록 유도 문구 표시 |
| 1 | 로그인 | 시작 버튼, 구글 또는 익명 로그인 | Firebase Auth 처리 | 로그인 실패 시 익명 로그인 안내 |
| 2 | 첫 정보 입력 | 학과, 학년, 닉네임, 학점 상한 선택 | 사용자 문서 저장 · 재방문 시 생략 | 학과 87개는 검색형 선택 |
| 3-1 | 과목 확인 | 추천 과목 확인, 제외, 추가 | 학과·학년 기준 전공기초·전공핵심 분반 표시 | 이미 들은 과목은 사용자가 제외 |
| 3-2 | 조건 입력 | 자유 문장 입력 | AI가 조건 JSON으로 변환 · 스키마 검사 | 변환 실패 시 체크박스 입력 전환 |
| 3-3 | 조건 확인 | 정리된 조건 수정, 동의 | 공강, 피할 교시, 점심, 학점, 필수 포함 과목 표시 | 처리 불가 요청은 「반영 불가」로 분리 표시 |
| 4-1 | 생성 대기 | 대기 | 코드가 조합 탐색 후 상위 3개 선정 | 대기 연출 표시 |
| 4-2 | 결과 비교 | 시간표 3개 비교 | AI가 안별 장단점 1~2문장 작성 | 0개면 충돌 원인과 완화 대안 표시 |
| 5-1 | 대표 선택 | 대표 지정 | 사용자별 대표 1개 덮어쓰기 | 변경 시 랭킹 점수 재계산 |
| 5-2 | 재생성 | 조건 수정 후 재생성 | 4-1로 복귀 | 사용자별 재생성 횟수 제한 |
| 5-3 | 직접 수정 | 분반 교체, 과목 추가·삭제 | 코드가 즉시 충돌·학점 상한 검사 | 충돌 시 저장 불가, 원인 표시 |
| 6-1 | 점수 공개 | 결과 확인 | 서버가 점수 계산 · 등급 도장 연출 · AI 칭호와 평론 | AI 실패 시 고정 칭호 사용 |
| 6-2 | 랭킹 반영 | 내 순위 확인, 공유 | 홈 랭킹 실시간 갱신 · 공유 카드 생성 | 자격 미달 시 미등록 사유 표시 |
| 7 | 경쟁률 | 과목별 경쟁률 확인 | 대표 시간표 집계 · 교양은 정원 대비 표시 | 전공은 정원 자료 확보 전까지 희망 인원만 표시 |

옛 시간표편성기 교훈(2026-08 작업로그):

- 강의실이 여러 곳인 강의는 첫 블록에만 요일 기재 → 생략 시 직전 요일 상속
- 여러 학과가 같은 과목번호 공유 → 식별 단위는 과목번호와 학과 조합
- 조합 실패 시 원인과 대안 제시가 핵심 기능

## 구현 순서

1. 자료 파싱과 시간표 계산, 단위 테스트
2. 조건 입력 → AI 변환 → 3안 생성 → 결과 비교 (로그인 없이도 동작)
3. 점수, 등급 연출, AI 칭호·평론
4. Firebase 로그인, 대표 저장, 실시간 랭킹
5. 직접 수정
6. 경쟁률, 공유 카드

14:00 개발 동결 기준 5~6번은 시간 부족 시 포기 대상. 13:30에 시연 가능한 상태 필요.

## 미결정

- 필수 과목 자료: 학교 자료 수령 전까지 「추천 과목」 표현 사용
- 전공 정원 자료 수령 여부
- Firebase 프로젝트: 대회용 신규 생성 권장, 관리자 결정 대기
- 랭킹 자격과 비교 범위: 전체 또는 학과별
